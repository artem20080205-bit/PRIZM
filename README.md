# PRISM 0.3.1 — чаты, хранилище и отмена передач

PRISM — мессенджер со своим сервером для двух участников. Репозиторий проекта: https://github.com/artem20080205-bit/PRIZM (в адресе используется PRIZM, название приложения — PRISM).

После переименования сохранены формат базы данных и папка server_data_v02. Новые приглашения начинаются с prism:, а старые приглашения lantern: также принимаются. При переходе с Lantern обновите оба клиента.

## Обновления через GitHub

Для первой установки из GitHub нужен Git for Windows и Python 3.13 (либо 3.12). Выполните в PowerShell:

```powershell
git clone https://github.com/artem20080205-bit/PRIZM.git
cd PRIZM
py -3.13 start.pyw
```

Если установлен Python 3.12, в последней команде укажите `-3.12`. Можно запускать start.pyw двойным щелчком.

Для последующих обновлений закройте PRISM, откройте терминал в папке проекта и выполните одну команду:

```powershell
.\update.cmd
```

Можно также запустить update.cmd двойным щелчком. Скрипт скачает код через `git pull --ff-only` и установит изменившиеся зависимости. Он не сбрасывает ваши изменения в коде и не удаляет данные. При ошибке установки зависимостей повторите обновление. После обновления запустите start.pyw. Обновляйте оба компьютера; на время обновления хозяина сервер будет недоступен, а временный интернет-адрес после запуска изменится.

Переход с архивной версии выполняется один раз: скачайте репозиторий через git clone в новую постоянную папку. На компьютере-хозяине при создании сервера выберите прежнюю папку server_data_v02 с перепиской и файлами. Её можно оставить по прежнему пути: не удаляйте старую папку. Для сохранения очереди докачек и настроек при закрытых приложениях скопируйте client_state.sqlite и preferences.json из старой папки в новую, если они существуют. На втором ПК достаточно новой копии приложения и приглашения.

В репозиторий включается только исходный код и тесты. Базы переписки, ключи доступа, настройки, серверные файлы, логи и окружение Python исключены из Git.

## Исправление передачи через интернет в 0.3.1

Файлы могут отправлять оба участника. Для интернет-загрузок размер блока уменьшен с 4 МиБ до 256 КиБ, тайм-аут отправки увеличен до 120 секунд. При сбросе соединения клиент автоматически переподключается до пяти раз и запрашивает сохранённую позицию на сервере. Если сервер получил блок, но ответ потерялся, данные не дублируются. Отмена работает и во время ожидания восстановления. После исчерпания попыток незавершённая передача остаётся доступной для ручной докачки.

Обновите оба приложения. Закройте старую версию, распакуйте новый архив и запустите start.pyw. Хозяину нужно выбрать прежнюю папку серверных данных и создать новое интернет-приглашение. Не удаляйте старую папку с данными и исходные файлы. Версия совместима с серверным протоколом 0.3.


## Новое в 0.3

Обновите сервер и оба клиента. Перед первым запуском новой версии закройте старое окно-хозяин сервера. Для сохранения существующей переписки при создании сервера выбирайте ту же папку server_data_v02. База 0.2 обновляется автоматически без удаления сообщений.

### Настройки и папка данных

Кнопка «Настройки» доступна в основном окне. Можно выбрать папку, которую приложение предложит при следующем запуске сервера. Смена пути не переносит и не удаляет данные: если выбрать пустую папку, будет создан новый сервер с новыми приглашениями. Хозяин видит реальный текущий путь и кнопку открытия папки.

Хозяин создаёт чаты кнопкой «Новый чат», переключение — в выпадающем списке. Все чаты этого сервера доступны обоим его участникам; это не отдельные группы с разным составом. Имеющаяся переписка находится в «Общем чате».

Для каждого чата и для всех чатов вместе показаны объём незавершённых отправок (кэш), готовых вложений и число сообщений. Есть три действия с подтверждением:

- «Очистить кэш»: удалить только незавершённые отправки; история и завершённые вложения остаются.
- «Удалить вложения»: удалить вложения и временные отправки; вместо сообщения с файлом появится отметка об удалении, текстовая переписка сохраняется.
- «Удалить всё»: удалить сообщения, вложения и временные отправки выбранного чата или всех чатов.

Очистка действует для всех участников. Чужие скачанные копии на их устройствах не удаляются. Настройки доступа и сами чаты сохраняются. Конфигурация, журналы программы и служебная база не удаляются. Операции не являются гарантированным криптографическим стиранием. Если файл сейчас скачивается, очистка попросит повторить её после завершения. После очистки размеры можно обновить, закрыв и открыв настройки. Только хозяин имеет право на эти операции; права проверяет сервер.

### Отмена передачи

Во время отправки или скачивания появляется кнопка «Отменить передачу». После нажатия приложение прерывает передачу и удаляет временные данные. Может потребоваться несколько секунд на завершение текущего сетевого запроса.

- Отмена скачивания удаляет только временный .part этой передачи. Уже существующий файл назначения и серверный оригинал сохраняются.
- Отмена отправки удаляет серверную копию и связанную запись о только что опубликованном файле, если отмена совпала с завершением проверки. Исходник на компьютере отправителя сохраняется.
- При временной недоступности сервера сохраняется очередь удаления. Она обрабатывается автоматически при подключении к тому же серверу (с тем же приглашением участника). Пока связи нет, немедленное удаление на удалённом ПК невозможно.
- Обычный обрыв связи без явной отмены сохраняет .part/частичную загрузку для докачки. При повторном выборе того же исходника загрузка возобновляется.
- Закрытие окна во время передачи запрашивает отмену; окно ждёт завершения обработки.

Текущий чат нельзя переключить во время передачи. Клиентские идентификаторы передач и очередь отмен хранятся локально в client_state.sqlite; токены доступа в эту базу не записываются. Незавершённые данные после аварийного выключения без явной отмены могут остаться до докачки или очистки хозяином.

### Проверки 0.3

13 тестов: старый протокол, разделение чатов, миграция базы 0.2, права хозяина, разные режимы очистки, отмена отправки/скачивания, сохранность исходника и файла назначения, отложенное удаление после восстановления связи. Дополнительно проверены два окна Qt, переключение чатов, обновление истории после очистки и реальная кнопка отмены. Через временный публичный HTTPS-канал проверены список чатов, отмена серверной отправки, сообщение и файл 256 КиБ. Проверки удаления выполнялись только на свежих тестовых данных.

## Быстрый запуск

На компьютере уже настроены Python 3.13 и зависимости в этой рабочей папке.
Откройте start.pyw двойным щелчком. При первом запуске на другом ПК понадобится Python 3.13 (или 3.12) x64 с Python Launcher; зависимости установятся автоматически. Запуск и ошибки записываются в launcher.log.

1. Нажмите «Создать сервер», оставьте настройки и подтвердите.
2. Нажмите «Включить интернет».
3. Первый раз загрузится официальный cloudflared (~53 МБ); SHA-256 проверяется перед запуском.
4. Дождитесь надписи «Интернет работает».
5. Нажмите «Приглашение другу» и передайте другу по доверенному каналу.
6. Друг запускает эту же версию, нажимает «Подключиться» и вставляет приглашение.

Оба ПК могут находиться в разных сетях. На роутерах ничего менять не нужно, отдельный VPN не нужен. Старые приглашения из версии 0.1 для этого не подходят.
При перезапуске интернет-канала адрес меняется — передайте новое приглашение.
Сервер работает, пока открыто окно хозяина. Не выключайте и не усыпляйте его ПК.
Для первого запуска на втором ПК потребуется интернет для зависимостей; сетевой компонент нужен только хозяину сервера.

## Что изменилось

- Временный публичный HTTPS-адрес создаётся автоматически через Cloudflare Quick Tunnel.
- Приглашение выдаётся после успешной проверки доступа по внешнему адресу.
- Сервер слушает только localhost, поэтому открывать порт Windows не требуется.
- Исправлены тёмный/белый текст и выделение в интерфейсе.
- Добавлен запуск на поддерживаемом Python вместо случайного Python 3.15.
- Исправлено завершение серверного процесса вместе с Windows launcher.

## Реальные ограничения

Это прототип транспортной части. Сквозное шифрование, проверка личности по ключам, ИИ, P2P и прямой обмен файлами ещё не реализованы. Сервер хранит переписку и файлы открыто. HTTPS защищает путь до Cloudflare, но Cloudflare завершает TLS и технически может видеть содержимое. Используйте вымышленные сообщения и несекретные файлы.

Quick Tunnel — сторонняя тестовая услуга без гарантии доступности и постоянного адреса. Доступность из разных сетей РФ нужно проверять отдельно. Возможны ограничения оператора и Cloudflare. Если туннель не запускается, приложение покажет ошибку; журнал tunnel.log находится рядом с кодом.

Это сознательный промежуточный шаг для проверки связи через интернет, а не законченная архитектура с собственным резервным узлом. Весь трафик этой версии идёт через Cloudflare, прямой передачи пока нет.

Файлы отправляются блоками до 4 МиБ с докачкой и SHA-256. Нет искусственного бытового лимита общего размера, но остаются место на диске, время, файловая система и ограничения туннеля. Сначала файл загружается на сервер целиком, затем становится доступен другу. Для докачки повторно выберите тот же неизменённый исходный файл либо тот же путь сохранения. Тест на десятках ГБ пока не проводился.

Приглашения многоразовые, содержат секрет доступа. Не публикуйте их. Два клиента должны использовать разные личности: хозяин — участник 1, друг — участник 2. В прототипе два участника сервера и несколько общих чатов. Администратор сервера контролирует оба секрета. Нет квот, защиты от участника-злоумышленника и аудита безопасности.

## PyCharm

Откройте всю папку PRISM. Выберите существующий интерпретатор .venv313/Scripts/python.exe и запускайте client.py. Сервер отдельно запускать не требуется. На другом ПК сначала запустите start.pyw и дождитесь установки окружения.

## Файлы

- client.py: интерфейс и жизненный цикл сервера/канала.
- server.py: API сообщений и файлов.
- network.py: приглашения и докачка.
- internet.py: проверяемая загрузка cloudflared.
- processes.py: остановка собственных дочерних процессов Windows.
- start.pyw: подготовка окружения и запуск.
- server_data_v02/: данные нового сервера, создаются автоматически.
- tools/cloudflared.exe: сетевой компонент, загружается автоматически, версия 2026.11.0.

Не отправляйте другу папку server_data_v02, журналы, .venv313 и свои приглашения в составе общедоступного архива. Архив исходников их не содержит.

Тестовый канал после проверки остановлен. Это проверка внешнего маршрута с одного ПК, а не измерение доступности со второго физического ПК/из другого города.
